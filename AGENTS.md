# Data repository guide

`wazootech/data` is Data's public working surface. It is not Data's runtime: identity,
conversations, and memory live wherever Data executes, not in this checkout.

## What belongs here

- Published artifacts for developers: guides, field notes, experiments, challenges, demos.
- Data's agent file at `agents/@wazootech/data/data.af`.
- Working notes that are safe for the public internet.

## What does not belong here

- Anything that is not safe to publish. This repository is public: no credentials, tokens,
  internal channel identifiers, customer data, or unredacted logs.
- Runtime source, deployment configuration, or memory stores, until
  [wazootech/computer#72](https://github.com/wazootech/computer/issues/72) decides where Data's
  source lives. Do not create an agent app here speculatively.
- A hand-edited `.af`. The agent file is a projection of Data's source, generated by
  `scripts/export-agent-file.ts` in `wazootech/computer` and verified by CI. Edit the source, then
  regenerate.

## Artifact rules

- Every published piece names its evidence: the released documentation or source revision it comes
  from, and how the claim was verified. If verification fails, abandon the piece rather than
  publishing it with a caveat.
- Prefer the smallest runnable reproduction over a description of one.

## Working rules

- Published content lands on `main`. Code, tooling, and layout changes go through a pull request.
- Develop in a Git worktree; do not create branches or commit inside a sibling checkout.
- Never commit credentials or `.env` files. Never create or delete repositories without human
  approval.

## Agent self-improvement (friction-gated)

File an issue only when real work surfaced a bug, a divergence from intended semantics, or a
genuine QoL gap that measurably cost time or trust. Never hunt for improvements. Finish the current
task first, check existing issues, then file one precise issue with a recommended fix.
